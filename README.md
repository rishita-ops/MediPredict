# MediPredict

A full-stack multi-disease risk prediction system covering **Heart Disease, Diabetes,
Liver Disease, and Kidney Disease** — one unified clinical decision-support app.

Built entirely by Rishita Sanghavi.

## What's inside

- **4 real clinical datasets** (not synthetic): UCI Heart Disease, Pima Indians
  Diabetes, Indian Liver Patient Dataset (ILPD), UCI Chronic Kidney Disease.
- **25 hand-designed engineered features** across the four diseases — ratios,
  interaction terms, and composite risk indices that don't ship with standard
  tutorials for these datasets.
- **Stacked ensemble model** per disease: Logistic Regression + Random Forest +
  XGBoost + SVM, combined by a meta Logistic Regression.
- **Real SHAP explainability** — genuine per-patient feature contributions computed
  live against the actual fitted model (KernelExplainer), not static notes.
- **Real model-disagreement uncertainty** — the standard deviation across the 4 base
  learners' predictions for that specific patient, surfaced as an "agreement" rating.
- **Real out-of-distribution detection** — flags any input value outside the 1st-99th
  percentile band the model was actually trained on.
- **Live what-if sliders** — drag a value and watch the prediction recalculate against
  the real model, debounced for responsiveness.
- **Framingham 2008 risk score** — the real, independently-published D'Agostino et al.
  formula, computed separately from the ML model, as a second opinion for heart disease.
- **PDF briefing packet export** — a clean, printable summary of any prediction with
  the SHAP breakdown and OOD flags included.
- **FastAPI backend** with a SQLite database that stores prediction history.
- **Clinical-clean 3-column dashboard** frontend (no build step) served by the backend.

## How to run it

```bash
cd backend
pip install -r requirements.txt

# train all 4 models + generate SHAP background samples and OOD percentile stats
# (only needed once, or whenever you change the code/data)
python -m app.train

# start on port 8001 (not 8000, in case you have another instance running)
python -m uvicorn app.main:app --reload --port 8001
```

Then open **http://localhost:8001** in your browser. That's it — one server, one
URL, the whole app.

API docs (auto-generated by FastAPI) are at **http://localhost:8001/docs**.

## API endpoints

| Endpoint | What it does |
|---|---|
| `GET /api/diseases` | Input schema for all 4 diseases |
| `POST /api/predict/{disease}` | Full prediction, saved to history, includes uncertainty + OOD, imputes blank fields from training medians |
| `POST /api/whatif/{disease}` | Lightweight prediction for slider dragging / live edits, not saved |
| `POST /api/explain/{disease}` | Real SHAP feature contributions for one patient |
| `POST /api/framingham` | Independent D'Agostino 2008 CVD risk score |
| `POST /api/differential` | Runs all 4 disease models from shared fields (age/BP/glucose/BMI), rest imputed |
| `POST /api/briefing/{disease}` | Generates a downloadable PDF briefing packet |
| `GET /api/history` | Past predictions |
| `GET /api/history/trend` | Past predictions for one patient label, oldest first — for the trend sparkline |
| `GET /api/reference-ranges/{disease}` | Published clinical normal ranges per field |
| `GET /api/glossary` | Plain-language definitions for clinical terms used in the UI |
| `GET /api/metrics` | Cross-validated model performance per disease |

## UI features

- **Reference range bars** under each lab input, sourced from real published normal ranges
- **Glossary tooltips** (the small "i" icons) with real clinical definitions
- **Live SHAP + live what-if** — editing any field after your first prediction auto-recalculates risk and SHAP, debounced
- **Imputation highlighting** — blank fields get a purple highlight and a note once you predict, since they were filled with a training-data median rather than a real value
- **Unit toggle** (US mg/dL ↔ SI mmol/L / µmol/L / g/L) for the fields where that distinction matters clinically
- **Cross-disease differential strip** — one click estimates risk across all 4 diseases from shared fields, clearly labeled when a disease is running on mostly-imputed data
- **Patient trend sparkline** — re-run a prediction under the same patient label to see risk-over-time

## What's real vs. what's a portfolio simplification

Everything above is a genuine calculation against real data and real models — not
placeholder UI. What this project intentionally does NOT claim: it is not
HIPAA-certified, does not integrate with EHR systems, and is not a substitute for
clinical judgment. Every prediction is a decision-support estimate.

## Retraining

Re-run `python -m app.train` any time — it re-downloads nothing (data is
already saved locally in `backend/data/`), retrains all 4 models fresh, and
regenerates the SHAP background samples, OOD percentile stats, and metrics.
